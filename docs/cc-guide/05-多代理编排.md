# 05 · 多代理编排

> **本章要回答的问题**：subagent、agent teams、workflows、跨会话消息 —— 四个都能"并行"，
> 该选哪个？答案：**看"计划由谁持有"**。


## 🎛️ 选型第一问：计划在谁手里？

这是官方给出的最干净的切分标准。

| 对比项 | Subagents | Skills | Agent Teams | Workflows |
|---|---|---|---|---|
| **是什么** | Claude 派生的一个 worker | Claude 遵循的指令 | 一个 lead agent 带一堆同伴会话 | 运行时执行的脚本 |
| **谁决定下一步** | Claude，逐轮决定 | Claude，按提示词 | lead agent，逐轮决定 | **脚本** |
| **中间结果在哪** | Claude 的上下文窗口 | Claude 的上下文窗口 | 共享任务列表 | **脚本变量** |
| **可复用的是** | worker 定义 | 指令 | 团队定义 | **编排本身** |
| **规模** | 每轮几个 | 同 subagent | 几个长跑同伴 | **每次运行几十到几百个 agent** |
| **被打断时** | 重启该轮 | 重启该轮 | 同伴继续跑 | 同会话内可恢复 |
| **token 成本** | 较低（摘要回主上下文） | 较低 | 较高（每个同伴是独立 Claude 实例） | 中高 |

> **一句话**：
> - **Claude 当编排者** → subagent / skill
> - **lead agent 当编排者** → agent teams
> - **代码当编排者** → workflows

**"把计划搬进代码"是 workflows 的核心价值**：
用 subagent 时，每个中间结果都进上下文窗口；用 workflow 脚本时，
循环、分支、中间结果都由脚本持有，**Claude 的上下文里只剩最终答案**。


## 🤖 Subagent：最常用的一档

### 它到底做了什么

subagent 在**自己的上下文窗口**里跑，有自己的系统提示词、自己的工具权限、自己的权限模式。
它**独立发起自己的请求**，这些请求**计入和主会话同一份用量配额**。

Claude 通过 agent 的 `description` 判断何时委派。描述匹配就委派，subagent 独立完成并返回结果。

### 内置的 4 个主力 subagent

| Agent | 模型 | 工具 | 用途 |
|-------|------|------|------|
| **Explore** | 主会话的模型（订阅/网关下走 `opus` 别名解析的模型） | 只读；**Write/Edit 被拒** | 文件发现、代码搜索、代码库探索 |
| **Plan** | 继承主会话（或 `CLAUDE_CODE_SUBAGENT_MODEL`） | 只读；**Write/Edit 被拒** | plan 模式下的代码库调研 |
| **General-purpose** | 同上，或 `CLAUDE_CODE_SUBAGENT_MODEL` | subagent 可用的全部工具（**含 Write / Edit**） | 复杂多步任务：既探索又动手 |
| **claude** | 无自有模型 | 同上 | 兜底；也是后台分发会话的默认 agent |

另有 2 个**辅助 agent**，由 Claude 自动调用、一般不用手动指定：

| Agent | 模型 | 什么时候被用 |
|-------|------|------------|
| **statusline-setup** | Sonnet | 你跑 `/statusline` 配置状态栏时 |
| **claude-code-guide** | Haiku | 你问 Claude Code 本身的功能时 |

> ⚠️ **"全部工具" ≠ "主会话的全部工具"**。subagent 继承主会话的工具后还要过**两层过滤**：
>
> | 层 | 生效范围 | 规则 |
> |----|---------|------|
> | **第一层** | **所有** subagent | 移除 `Agent`（到达深度上限时）、`AskUserQuestion`、`EndConversation`、`EnterPlanMode`、`ExitPlanMode`（`permissionMode: plan` 除外）、`ScheduleWakeup`、`WaitForMcpServers`、`Workflow` —— **即使写进 `tools` 字段也留不住** |
> | **第二层** | **后台** subagent（**默认就是后台**） | 内置工具只剩 `Read` `Grep` `Glob` `LSP` `Bash` `PowerShell` `Edit` `Write` `NotebookEdit` `WebFetch` `WebSearch` `TodoWrite` `Skill` `ToolSearch` `EnterWorktree` `ExitWorktree` `Monitor` `TaskStop` `SendMessage` `Artifact`，**外加 `SubagentHandback`**（需要回报结果给调用方的 subagent）；其余内置工具一律移除，**MCP 工具全保留** |
>
> **三个例外**：
> - fork **跳过这两层过滤**，拿到主会话的原样工具池；
> - v2.1.280 起后台 subagent 才重新能用 `LSP`；
> - **macOS / Linux / WSL** 上，主会话没有 `Glob` / `Grep` 时 subagent 仍能拿到它们
>   （**原生 Windows 没有这个例外**）。
>
> 官方原文：[sub-agents · Available tools](https://code.claude.com/docs/en/sub-agents#available-tools)

> **Explore / Plan 启动时不会加载 CLAUDE.md 和 git status 快照** —— 这是它们快且便宜的原因。
> 其他内置和自定义 subagent 默认会加载；给自定义 agent 设 `omitClaudeMd: true` 可以关掉。

### 自定义 subagent 的 frontmatter 全表

只有 `name` 和 `description` 是必填，其余省略即可。**字段名是 camelCase，写错会被静默忽略**。

| 字段 | 说明 |
|------|------|
| `name` | 唯一标识，≤256 字符。不能含 `:`（留给插件作用域）。**文件名不必与之一致** |
| `description` | 何时该委派给它 |
| `tools` | 逗号分隔字符串或 YAML 列表。省略则继承全部 |
| `disallowedTools` | 从继承/指定列表中移除。**带 specifier 的条目（如 `Bash(git push *)`）会移除整个工具** |
| `model` | `sonnet` / `opus` / `haiku` / `fable` / 完整 model ID / `inherit` |
| `permissionMode` | `default` / `acceptEdits` / `auto` / `dontAsk` / `bypassPermissions` / `plan` / `manual` |
| `maxTurns` | 最大轮数。到达上限时输出被标记为 partial，Claude 可以 **resume** 续跑 |
| `autoCompactWindow` | 为该 subagent 降低自动压缩阈值（100000–1000000 tok） |
| `skills` | **启动时预加载**的 skill（注入完整正文，不只是 description） |
| `mcpServers` | 该 subagent 可用的 MCP server |
| `hooks` | 作用于该 subagent 的生命周期 hook |
| `memory` | `user` / `project` / `local` —— 持久记忆范围 |
| `background` | `true` = 即使 Claude 说要等也留在后台 |
| `omitClaudeMd` | `true` = 启动时不加载 user/project/local CLAUDE.md（托管策略文件仍加载） |
| `effort` | `low` / `medium` / `high` / `xhigh` / `max` |
| `isolation` | `worktree` = 在临时 git worktree 里跑，默认从**默认分支**分支（不是父会话 HEAD） |
| `color` | 任务列表与 transcript 里显示的颜色 |
| `initialPrompt` | 作为主会话 agent（`--agent`）运行时自动提交的第一轮用户消息 |
| `experimental.cacheTtl` | `5m` / `1h` —— 该 subagent 请求的 prompt 缓存寿命 |

> ⚠️ **`experimental` 是嵌套 map**，`cacheTtl` 要写在它里面，不能写在顶层。

### ⚠️ 这些文件会被**静默跳过**（不报错）

在 `agents/` 目录里的文件，frontmatter 出现以下问题时 Claude Code **不加载也不提示**，
只往 debug log 写一条：

- 没有 `name` → 当成"放在 agent 旁边的文档"
- 开头的 `---` **不是文件第一行** → 当成没有 frontmatter
- `name` 以 `-` 开头、含 `:`、或超过 256 字符 → 跳过
- 有 `name` 但没有 `description` → 跳过
- **YAML 解析失败** → 一个字段都不读，跳过

**排查方法**（v2.1.296+）：

```bash
claude --debug
# 然后在 ~/.claude/debug/<session-id>.txt 里搜 "does not recognize or apply"
# 会列出最多 5 个不认识的顶层字段，并给出最可能的正确名称
```

**批量检查**：

```bash
claude plugin validate .claude/agents      # 检查 frontmatter 能否解析
```

> 这条命令只检查你指名的那**一个目录**，且**不会**标记"能解析但没有 `name`"的文件。

#### 本仓库实测：4 个文件被静默忽略

`claude --debug` 的启动日志把话说得很直白（agent 相关的三个文件）：

```text
[WARN] Failed to parse YAML frontmatter in .claude\agents\python-zen-coding-expert.md: YAML Parse error: Unexpected token
[WARN] Failed to parse YAML frontmatter in …\story-generator.md: YAML Parse error: Multiline implicit key
[WARN] Failed to parse YAML frontmatter in …\dev-planner.md: YAML Parse error: Multiline implicit key
```

根因都是 YAML 写法，两个典型错误：

| 错误写法 | YAML 报什么 | 修法 |
|---------|-----------|------|
| `argument-hint: [topic] [parallel]` | `Unexpected token` | 写成 `argument-hint: "[topic] [parallel]"`（加引号） |
| `description: 多行文本`（没有 `\|` 或 `>`） | `Multiline implicit key` | 改成块标量 `description: \|` + 缩进正文 |
| `description: 一句话: 带冒号` | `mapping values are not allowed here` | 整句加引号，或用块标量 |

> **规律**：YAML 的"隐式多行"和"值里含 `: `"是同一类坑。
> **frontmatter 里的多行文本一律用 `|` 块标量**，这一条能消灭 80% 的解析失败。

### 嵌套与并发

| 限制 | 默认值 | 调整变量 |
|------|-------|---------|
| **嵌套深度** | 主会话之下 **3 层** | `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`（设 `1` = 关闭嵌套） |
| **并发数** | 同时运行 **20 个**时，新的 Agent 调用失败并提示 Claude 不要重试 | `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` |

- 会话总数**无上限**，只限并发
- 深度到达上限时，除 fork 外**所有 subagent 都被剥夺 `Agent` 工具**
- `ultracode` 开启时会话**不受并发限制**
- workflow 的 agent 和 agent team 的同伴**走各自的限制**，不占 subagent 的槽

> **本仓库**：`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 和
> `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 都未设置，走默认值（3 层 / 20 并发）。


## 👥 Agent Teams：多个 Claude 实例组队

> ⚠️ **实验特性，默认关闭**。需要 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`。

一个会话当 **team lead**，分配任务、综合结果；teammate 各自独立上下文，**直接互相通信**，
你也可以绕过 lead 直接跟某个 teammate 说话。

| 对比项 | Subagents | Agent Teams |
|---|-----------|-----------|
| 上下文 | 自己的窗口；结果回到调用方 | 自己的窗口；完全独立 |
| 通信 | 返回结果给调用方 | **队友之间直接互发消息** |
| 协调 | 主 agent 管理全部 | **自发协调 + 共享任务列表** |
| 适合 | 只需结果的聚焦任务 | 需要讨论、协作、互相挑战的任务 |
| token | 较低 | **较高**（每个队友是独立 Claude 实例） |

**最强的使用场景**（官方原话）：

- **研究与评审**：多个队友同时调查一个问题的不同方面，然后**互相挑战彼此的发现**
- **新模块/新功能**：队友各占一块，互不干扰
- **竞争性假设调试**：队友并行验证不同理论，更快收敛
- **跨层协作**：前端、后端、测试各一个队友

**不擅长的场景**：顺序任务、**改同一个文件**、依赖很多的活 —— 这些用单会话或 subagent 更有效。

> **本仓库已开启**：`settings.json` 里已有 `"CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"`。
> 但注意官方明确的限制：会话恢复、任务协调、关闭行为都有已知问题。


## ⚙️ Workflows：把计划写进脚本

一个 **JavaScript 脚本**编排大量 subagent。Claude 根据你的描述写这个脚本，
运行时在后台执行，**你的会话保持可响应**。

- 所有付费计划、Anthropic API、Bedrock、Vertex AI、Foundry 可用
- Pro 用户需要在 `/config` 里打开 Dynamic workflows
- 内置 `/deep-research` 可直接体验

**workflow 的独特能力：对抗式复核**

```javascript
// 伪代码结构
const results = await pipeline(
  DIMENSIONS.map(d => () => agent(d.prompt, { schema: FINDINGS_SCHEMA })),
  results => parallel(results.flatMap(r =>
    r.findings.map(f => () =>
      agent(`Adversarially verify: ${f.title}`, { schema: VERDICT_SCHEMA })
        .then(v => ({ ...f, verdict: v }))
    )
  ))
);
const confirmed = results.flat().filter(Boolean).filter(f => f.verdict?.isReal);
```

这个模式 subagent 做不到 —— 因为**编排逻辑在代码里，不在 Claude 的上下文里**。

### 三条纪律（官方工作流编写参考）

1. **纯字面量开头**：`export const meta = { name, description, phases }` 必须是无变量的字面量
2. **中间结果放脚本变量**，不占 Claude 上下文
3. **分阶段 + 每阶段独立验证**：一个维度的审查完成后立刻验证，不要等全部跑完


## 📨 跨会话消息：让多个终端协同

一个会话把消息送到**另一个**会话。消息就是一段文字 —— 不是对方的对话历史，也不是文件。

**适用场景**：

| 场景 | 怎么用 |
|------|--------|
| **交接发现** | 一个会话发现破坏性变更 → 通知另一个正在改同一区域的会话 |
| **协调并行 worktree** | 告诉其他会话"我这边落地了什么" |
| **问长任务状态** | 让迁移/测试跑完后回报给盯着它的会话 |
| **跨机器** | 触达另一台机器或云端的会话 |

**工具**：`ListAgents`（发现目标）+ `SendMessage`（发送）。
**你不需要自己调这两个工具** —— Claude 会调。

**@ 提及其他会话**（v2.1.232+）：

```text
Let @api-worker know the schema migration finished
```

带空格的会话名要用引号：`@"release notes"`。

**平台要求**：
- macOS / Linux / WSL2 → v2.1.224+
- **原生 Windows → v2.1.234+**
- 满足条件时**默认开启**，无需配置

**关键限制**：消息**只是一段文字**。
要搬整个会话或上下文，用 **resume session**，不是发消息。

> **本仓库**：多个插件并行开发时，这条通道可以让"改了 `plugin.json` 的那个会话"
> 主动通知"正在改 CI 路径的那个会话"，省掉你手动复述。


## 🔀 Fork：派生当前对话

`/subtask` 从当前会话派生一个**继承完整上下文**的 fork。

| 对比项 | Fork | 普通 subagent |
|---|------|--------------|
| 上下文 | **继承当前对话** | 全新上下文窗口 |
| 用途 | 换个方向试同一份上下文 | 隔离的聚焦任务 |
| 深度上限行为 | 保留 `Agent` 工具，但调用报错 | 被剥夺 `Agent` 工具 |

fork 适合"同一份上下文，换个假设再试一遍"。

### ⚠️ 本仓库自己的插件：skill 一个都没加载

本仓库旗舰插件的 skill 一个都没加载，agent 却加载了 1 个。

**根因是缓存没跟上，不是布局写错**：本机插件缓存同步的是**远端已发布版本**，
而仓库里的 skill 迁移（`skills/<name>.md` → `skills/<name>/SKILL.md`）还没 push。
用 `claude --plugin-dir ./plugins/evolutionary-biology-expert` 就地加载，
日志立刻变成 `Loaded 4 skills from plugin evolutionary-biology-expert`。
完整日志与修法见 [06 插件与市场 · 本仓库的市场审计](06-插件与市场.md#本仓库的市场审计)。

### ⚠️ 一个具体问题：插件 agent 引用了不存在的 skill

`plugins/hybrid-speciation-expert/agents/hybrid-speciation-analyst.md` 调用：

```text
activate_skill("expert-network-mapping")
activate_skill("critical-thinking-analysis")
activate_skill("temporal-dynamics-analysis")
```

**这三个 skill 在任何插件里都不存在**。实际对应的是
`evolutionary-biology-expert` 的 `six-dimensions-analysis`。
该 agent 还拼接了一个不存在的 `"theoretical_assessment"` 阶段。

**影响**：hybrid-speciation 插件的分析流程在 Claude 实际调用时会**取不到这些模块**，
要么模型自己编一个结构，要么流程直接断掉。

**修法（二选一）**：

| 方案 | 做法 | 适合 |
|------|------|------|
| **A. 改名对齐** | 把三个调用改成 `six-dimensions-analysis` + 该插件自己的 `hybrid-origin-analysis` / `speciation-mechanism-advising` | 语义最贴近真实能力 |
| **B. 补齐 skill** | 新建 3 个 skill 目录并写正文 | 确实需要这三个独立能力 |

> 这个问题是本次迁移过程中发现的**存量缺陷**，不在"迁移 skill 到 `<name>/SKILL.md`"的修复范围内，
> 但值得单独修。修法 A 只需改一个文件的 4 行。


## ✅ 选型速查

| 需求 | 选型 | 说明 |
|------|------|------|
| 不需要并行，只是想固化一段流程 | **Skill** | instructions，Claude 遵循 |
