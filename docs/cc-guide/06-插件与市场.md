# 06 · 插件与市场

> **本章要回答的问题**：插件目录该怎么摆、manifest 里每个字段是什么语义、
> 一个插件到底要花掉多少上下文、发布到市场前要检查什么？
>
> 答案：**插件是"复制到缓存再加载"的模型**，不是"从仓库目录直接读"——
> 这个机制决定了后面几乎所有坑。


## 🧩 插件是什么

插件是**一组打包分发的扩展**：skills、commands、agents、hooks、MCP servers、LSP servers、
output styles、workflows、themes、monitors，可以一次性给用户装上一整套能力。

**关键机制：插件不是就地加载的。**

| 插件来源 | 加载方式 | 改了源码会生效吗 |
|---------|---------|----------------|
| `--plugin-dir` | **就地加载**，永不复制 | ✅ 下次启动或 `/reload-plugins` 即生效 |
| 本地路径市场的相对路径插件 | **就地加载** | ✅ 同上 |
| **其他所有市场插件** | **复制进 `cache/<市场>/<插件>/<版本>/`** | ❌ **必须刷新安装** |

所以：**改了仓库里的插件源码，本机的插件不会自动更新。**
这是新手最常见的"我改了怎么没生效"。

### 磁盘布局

所有路径相对 `~/.claude/plugins/`（可用 `CLAUDE_CODE_PLUGIN_CACHE_DIR` 改）：

| 路径 | 内容 |
|------|------|
| `cache/<市场>/<插件>/<版本>/` | 每个已安装版本一个目录。**`${CLAUDE_PLUGIN_ROOT}` 指向这里** |
| `data/<插件 id>/` | 插件的持久数据目录，**`${CLAUDE_PLUGIN_DATA}`** 指向这里。更新时保留 |
| `marketplaces/<市场名>/` | 从 GitHub / URL 添加的市场副本 |
| `installed_plugins.json` | **已安装插件的登记表**（哪个版本、装在哪个 scope） |
| `known_marketplaces.json` | 已添加市场的登记表（来源、位置、最后更新时间） |

> **两个变量别搞混**：
> `${CLAUDE_PLUGIN_ROOT}` 随版本变化（插件更新后路径就变了），
> `${CLAUDE_PLUGIN_DATA}` 跨更新保留。要放持久文件就用后者。

### 版本号是怎么算出来的

Claude Code 用"版本"来判断要不要更新。解析顺序：

1. `plugin.json` 里的 `version`
2. 市场条目里的 `version`
3. 都没有时，按来源类型算：

| 来源类型 | 无 `version` 字段时的版本 |
|---------|----------------------|
| `github` / `url` / `git-subdir` | 提交 SHA 前 12 位 |
| `archive` | SHA-256 摘要前 12 位 |
| 本地目录（都不是 git 仓库） | `unknown` |
| `npm` | `unknown` |

> ⚠️ **manifest 里写死了 `version` 就会卡住版本**：
> 作者推了新 commit，但 `version` 字符串没改 → 所有人都停留在旧副本。
> 想让用户跟着 commit 走，就**两个地方都不写 `version`**。


## 📄 `plugin.json`：插件的 manifest

**必须放在 `.claude-plugin/plugin.json`**，而且**插件的其他文件要放在插件根目录下，不能塞进 `.claude-plugin/`**。

```json
{
  "name": "deploy-tools",
  "displayName": "Deploy Tools",
  "version": "1.2.0",
  "description": "Deployment commands, a review agent, and a status monitor",
  "author": { "name": "Example Team", "email": "dev@example.com" },
  "homepage": "https://example.com/docs/deploy-tools",
  "repository": "https://github.com/example/deploy-tools",
  "license": "MIT",
  "keywords": ["deployment", "ci"],
  "dependencies": ["secrets-vault"],
  "userConfig": {
    "api_token": { "type": "string", "title": "API token", "sensitive": true }
  }
}
```

**只有 `name` 是必填。** 没有 manifest 也能加载插件 —— Claude Code 会扫描标准布局。

### 各组件字段的默认位置与语义

| 组件 | 默认位置 | 内容 |
|------|---------|------|
| Manifest | `.claude-plugin/plugin.json` | 元数据。可选 |
| Skills | `skills/` | **每个技能一个 `<name>/SKILL.md` 目录** |
| Commands | `commands/` | 平铺的 Markdown 命令文件 |
| Agents | `agents/` | Agent Markdown 文件（子目录算 agent 名的一部分） |
| Hooks | `hooks/hooks.json` | 钩子配置 |
| MCP servers | `.mcp.json` | MCP server 定义 |
| LSP servers | `.lsp.json` | LSP server 配置 |
| Output styles | `output-styles/` | Output style Markdown |
| Workflows | `workflows/` | Workflow `.js` 文件 |
| Themes | `themes/` | Theme JSON |
| Monitors | `monitors/monitors.json` | monitors 数组 |
| Executables | `bin/` | **插件启用时，这个目录在 Bash 的 `PATH` 上** |
| Settings | `settings.json` | `agent` 与 `subagentStatusLine` 默认值 |

### ⭐ 组件字段的三种合并语义（最容易搞错的地方）

| 语义 | 组件 | 含义 |
|------|------|------|
| **替换**默认位置 | `commands`、`agents`、`outputStyles`、`workflows`、`experimental.themes`、`experimental.monitors` | 设了就**不再扫描**默认目录 |
| **追加**到默认位置 | `skills` | 默认 `skills/` **照样扫描**，manifest 里写的额外加载 |
| **合并** | `hooks`、`mcpServers`、`lspServers` | 默认文件先加载，manifest 声明的合并进去 |

> **"替换"和"追加"的区别在 `skills` 上最要命**：
> `skills` 是**追加**语义 —— 写 `"skills": ["./skills/"]` 不会关掉默认扫描，只是又加了一遍。
> 其他组件是**替换**语义 —— 写了 `commands` 就**不再**扫 `commands/` 目录了。

**"替换"带来的告警**：如果插件有 `commands/` 目录，manifest 又设了 `commands` 键，
Claude Code 会警告：

```text
Default commands/ folder is ignored because the manifest sets "commands"
```

**消除告警的办法**：把键指向该目录**里面的文件**，而不是目录本身：

```json
"commands": ["./commands/deploy.md"]     ← 不告警
"commands": ["./commands/", "./extras/"]  ← 显式列出默认目录，不告警
```

### 路径规则

- 所有组件路径**相对插件根**，且**必须以 `./` 开头**。`commands/foo.md`（没有 `./`）会校验失败
- `skills` 额外接受 `"."`（表示插件根）。**v2.1.221 之前 `"."` 会校验失败**，要兼容老版本就写 `"./"`
- 路径**必须存在**，且**必须解析在插件根之内**：
  - 含 `..` → 报 `Path contains ".." which could be a path traversal attempt`
  - 不存在 → 报 `Path not found`
  - 解析到插件外 → `path escapes plugin directory`
- **组件路径必须用正斜杠**。macOS/Linux 上路径里有反斜杠会被拒（即使还在插件内），
  所以 `\` 写的路径只在 Windows 上能用

### 未识别的字段

| 位置 | 行为 |
|------|------|
| **顶层未知字段** | **被剥离**，插件照常加载。`claude plugin validate` 报 warning |
| `userConfig` 选项 / `channels` 条目 / `lspServers` 配置 / `monitors` 条目里的未知键 | **是错误**，插件不加载 |

> ⚠️ **顶层写错字段名 = 静默失效**。
> 这就是为什么 `claude plugin validate` 要配 `--strict` 跑 CI。


## 🏪 `marketplace.json`：市场的 manifest

同样放在 `.claude-plugin/marketplace.json`。

### 顶层字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 市场标识符。字母数字 `.` `_` `-`，不能有 `..` |
| `owner` | object | 维护者信息，`name` 必填 |
| `plugins` | array | 插件条目数组。**每个条目独立校验，一个坏条目不会让整个市场挂掉** |
| `$schema` | string | JSON Schema URL，给编辑器补全用。**加载时忽略** |
| `description` | string | 市场描述，缺失时 validate 会警告 |
| `version` | string | 市场 manifest 版本 |
| `metadata.description` / `metadata.version` | string | 上面两个的备用位置 |
| `metadata.pluginRoot` | string | 裸插件名的解析根目录 |
| `forceRemoveDeletedPlugins` | boolean | `true` 时，用户移除的插件会在用户机器上被卸载 |
| `allowCrossMarketplaceDependenciesOn` | array | 允许哪些市场的插件作为本市场插件的依赖被安装 |
| `renames` | object | 插件改名映射，值可以是 `null`（表示删掉了） |

### 插件条目

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 插件标识符。**用户安装时 `@` 后面用的是这个名字**，即使 `plugin.json` 里的 `name` 不同 |
| `source` | string \| object | 从哪里取 |
| `description` | string | 显示在 `/plugin` 列表里 |
| `version` | string | **条目设了而 `plugin.json` 也设了 → `plugin.json` 优先**，validate 会警告 |
| `category` | string | **自由文本分类** |
| `tags` | array of strings | **自由文本标签**，用于搜索 |
| `strict` | boolean | 默认 `true`。见下节 |
| `dependencies` | array | 依赖的插件 |
| `defaultEnabled` | boolean | 默认 `true`。用户在 `enabledPlugins` 里没设置时是否默认启用 |
| `displayName` | string | UI 显示名 |
| `metadata` | object | 自由字段，Claude Code 不读 |
| `headers` / `headersHelper` | object / string | archive 下载的鉴权头 |

### `source` 的七种类型

| 类型 | 字段 | 说明 |
|------|------|------|
| **相对路径** | 字符串本身 | 市场目录里的子目录，**必须以 `./` 开头**（除非用 `metadata.pluginRoot` 写裸名）。`"."` 表示根 |
| `github` | `repo`, `ref`, `sha` | GitHub 仓库，`owner/repo` 形式 |
| `url` | `url`, `ref`, `sha` | 任意 git 仓库的 URL |
| `git-subdir` | `url`, `path`, `ref`, `sha` | git 仓库的某个子目录（稀疏检出） |
| `npm` | `package`, `version`, `registry` | npm 包或 tarball 链接 |
| `archive` | `url`, `sha256` | HTTPS zip |
| `command` | `command`, `timeout`, `mode` | 由命令打印出的目录 |

`ref` 是分支或 tag（默认仓库默认分支），`sha` 是 40 位小写 commit SHA。
**两者都设时检出 `sha`** —— 即使 `ref` 指的分支已被删除也能装上。

### ⭐ `strict`：条目与 manifest 谁说了算

**`plugin.json` 存在时，它是权威。** `strict` 决定条目里声明的组件字段怎么处理：

| `strict` | `plugin.json` | 条目声明了组件字段 | 结果 |
|---------|--------------|------------------|------|
| 任意 | 无 | 任意 | **条目本身就是 manifest** |
| `true`（默认） | 有 | 任意 | `plugin.json` 是权威，**条目的组件字段追加上去**；`hooks` 的 matcher 按事件**替换** manifest 的 |
| `false` | 有 | 无 | 同 `true` |
| `false` | 有 | **有** | ⚠️ **冲突，插件加载失败**：`Plugin <name> has conflicting manifests` |

**还有一条容易忽略的**：条目里的 `mcpServers` / `lspServers` / `userConfig` / `channels`
在 `plugin.json` 存在时**完全不生效** —— 必须在 `plugin.json` 里声明。

**条目里的 `hooks` 只支持内联对象**。写成文件路径或数组，
`claude plugin validate` **会通过**，但那些 hook **永远不运行**，
`/plugin` 的 Errors 页会报 `not yet supported in a marketplace entry`。

### 元数据优先级

| 字段 | 谁赢 |
|------|------|
| `defaultEnabled`、显示类字段（`displayName` / `description` / `author` / …） | **条目赢** |
| `version` | **`plugin.json` 赢** |
| `name` | `enabledPlugins` 用条目名；组件命名空间用 manifest 名 |

### ⚠️ 未知键是静默的

> *"Claude Code ignores an unknown top-level key or plugin-entry key rather than
> rejecting it, so a typo loads silently."*（官方原话）

`claude plugin validate` 会把每个未知键报成 **warning** —— 所以 CI 里一定要加 `--strict`。

### 保留名称

市场名不能叫这些（部分）：

`claude-code-marketplace`、`claude-code-plugins`、`claude-plugins-official`、
`anthropic-marketplace`、`anthropic-plugins`、`agent-skills`、`claude-community`、
`anthropic-plugin-directory`、`claude-plugin-directory`、`inline`、`builtin`、`skills-dir`、
`synced`、`npm`、`pip`、`uv`、`cargo`、`github`、`gh`，以及 `claudeai-` 开头的名字。

还有两个隐蔽规则：

- **换个拼写也算保留**：只差一个结尾的点、或把连字符换成别的符号 → `claude.code.plugins` 算 `claude-code-plugins`
- **JS 对象原型上的名字**：`constructor`、`hasOwnProperty`、`toString`、`valueOf` 等


## 🔍 `claude plugin validate`：CI 门禁

```bash
claude plugin validate ./my-plugin --strict
```

### 退出码

| 退出码 | 判定行 | 含义 |
|-------|--------|------|
| `0` | `Validation passed` / `Validation passed with warnings` | 加载没问题（`--strict` 下连 warning 都没有） |
| `1` | `Validation failed` / `Validation failed (--strict treats warnings as errors)` | 有 error，或在 `--strict` 下有 warning |
| `2` | `Unexpected error during validation: <原因>` | **校验器自己挂了**（比如路径读不了） |

> **注意**：`Advice` 块（见下）**不影响退出码**，`--strict` 也不影响。

### `--json` 输出

顶层字段：

| 字段 | 说明 |
|------|------|
| `success` | 与退出码一致的判定 |
| `strict` | 本次是否把 warning 当 error |
| `target` | 实际校验的路径 |
| `manifest` | manifest 自身的结果，没有 manifest 时为 `null` |
| `contents` | 逐文件结果，每项含 `file` / `errors` / `warnings` / `notes`。**干净的文件不出现** |
| `advice` | README 建议条目，每项含 `file` / `message` / `installLine` |

退出码 `2` 时 stdout 什么都没有，错误信息走 stderr。

### `Advice` 块：README 必须有安装行

如果插件的 README 里**没有一行能安装它的命令**，validate 会给一条 Advice（v2.1.295+）：

```text
ℹ Advice (does not change the verdict):

  ❯ …/plugins/deploy-helper/README.md: This README has no line that installs
    "deploy-helper" from a marketplace. Add the install line, which works in
    one step on Claude Code 2.1.275 or later.
      /plugin install deploy-helper --marketplace acme/tools
```

**什么算"安装行"**（`plugin install` 或 `plugin i` 后面同一行）：

- `<插件>@<市场>`，如 `/plugin install deploy-helper@acme-tools`
- 插件名 + `--marketplace <来源>`，如 `/plugin install deploy-helper --marketplace acme/tools`

> 把带 `<owner>/<repo>` 占位符的建议原样贴进去**不会**消掉 Advice —— 要填真实来源。

### 校验器**不**检查的东西

| 文件 | 行为 |
|------|------|
| 插件根目录的 `SKILL.md` | **不检查** |
| 插件根目录的 `CLAUDE.md` | **会警告**（根目录的 `CLAUDE.md` 不会作为上下文加载） |
| 市场里**其他目录**下的插件文件 | **不打开**。要检查得逐个插件目录跑 validate |

### 校验器会额外检查 MCP

| 级别 | 检查项 |
|------|--------|
| **Error** | 加载时会被丢弃的条目、manifest 没声明的 `${user_config.KEY}` 引用、不是合法绝对 URL 的远程 `url` |
| **Warning** | 指向非 loopback 主机的 `http://` / `ws://` URL、看起来像明文凭据的 header 值 |


## 💰 一个插件到底花多少钱

**每个启用了插件的会话，都会把它的 skill / agent / command 的名字和 description
放进上下文 —— 哪怕这个插件一次都没被用到。**

官方给了专门的命令：

```bash
claude plugin details <name>
```

> ⚠️ **这条命令读的是"安装缓存"，不是仓库目录。**
> 本仓库的插件还没 push，缓存里是**旧平铺布局**的版本 ——
> 直接跑 `claude plugin details evolutionary-biology-expert` 只会得到
> `Skills (1) evo-analyze` / `Always-on: ~232 tok`，
> 而不是下面实测的 4 个 skill。
> 要量**仓库里**的真实成本，用 `claude --plugin-dir ./plugins/<name>` 就地加载后再看。
> 缓存同步机制的完整说明见 [07 排错手册 · 坑 2](07-排错手册.md#坑-2-插件-skill-一个都没加载-缓存是迁移前的旧快照)。

实测本仓库的插件（`--plugin-dir` 就地加载）：

```text
evolutionary-biology-expert 0.1.2
  Component inventory
    Skills (4)  academic-literature-analysis, data-integration-formatting,
                search-term-optimization, six-dimensions-analysis
  Projected token cost
    Always-on:   ~386 tok   added to every session

  Per-component (rounded)
    component                     always-on  on-invoke
    academic-literature-analysis       ~100      ~2.3k
    data-integration-formatting        ~100      ~1.6k
    search-term-optimization            ~90      ~1.9k
    six-dimensions-analysis            ~100      ~1.1k
```

| 插件 | skill 数 | always-on | on-invoke（单次） |
|------|---------|-----------|----------------|
| evolutionary-biology-expert | 4 | ~386 tok | 1.1k–2.3k |
| crop-breeding-expert | 3 | ~370 tok | 1.9k–2.1k |
| hybrid-speciation-expert | 3 | ~360 tok | 1.5k–1.7k |
| evolutionary-ecology-expert | 3 | ~350 tok | 1.9k–2.5k |
| infographic-viz | 1 | ~214 tok | ~2.3k |
| slidev-generator | 1 | ~211 tok | ~570 |

**要点**：

1. **always-on 是每个人都要付的**，哪怕一次都没调用过
2. **on-invoke 是每次调用都要付的** —— 所以 skill 正文要写得刚好够用
3. Hooks 和 MCP servers **不计入**这个估算（hook 没有模型上下文成本；
   MCP 的工具 schema 在运行时才解析，要看 `/context` 的 `MCP tools` 分类）
4. Commands **和 skills 一起统计**（命令在 `Skills` 那一栏里）

**降低 always-on 的办法**（官方建议）：

- 缩短 skill / agent 的 `description`
- 把大插件**拆开**，让用户只装需要的部分

> ⚠️ **缩短 description 有副作用**：description 正是 Claude 用来匹配请求的东西，
> 削太狠会让 skill 根本不触发。削完要用 `tool_used: Skill` 这个 grader 验一遍触发率。


## 🔍 本仓库的市场审计

`.claude-plugin/marketplace.json`（v0.1.4）：

```json
{
  "name": "cc_plugins",
  "owner": { "name": "gqy20" },
  "plugins": [
    { "name": "evolutionary-biology-expert", "source": "./plugins/evolutionary-biology-expert",
      "description": "...", "category": "research" },
    ...
  ]
}
```

| 检查项 | 状态 |
|--------|------|
| 插件的 `source` 都是相对路径 `./plugins/<name>` | ✅ 正确 |
| `category` 字段（research / expert-advisor / utility） | ✅ **是官方条目字段**，自由文本 |
| `strict` | 未声明 → 默认 `true` |
| `$schema` | 指向 SchemaStore 的 `claude-code-marketplace.json` ✅ |

### `$schema`：Anthropic 官方的两个地址都已失效

官方文档确认 `$schema` 是合法字段（"JSON Schema URL for editor autocomplete.
Claude Code ignores it at load time"），但**没有公布任何 schema 地址**。
实测（2026-10-30）：

| 地址 | 状态 |
|------|------|
| `https://anthropic.com/claude-code/marketplace.schema.json` | ❌ **404**（anthropic.com 已变成营销站） |
| `https://anthropic.com/claude-code/plugin.schema.json` | ❌ **404**（同上） |

二进制（2.1.314）里只内嵌了 **`plugin.schema.json`** 这一个地址 ——
**根本没有 marketplace 的 schema**；而它内嵌的那个现在也是 404。

**可用替代：SchemaStore**（社区维护，活的）：

| 用途 | 地址 |
|------|------|
| `marketplace.json` | `https://www.schemastore.org/claude-code-marketplace.json` |
| `plugin.json` | `https://www.schemastore.org/claude-code-plugin-manifest.json` |

两者都是 `application/json`、JSON Schema draft-07。
本仓库的 `marketplace.json` + 6 个 `plugin.json` 已全部切过去，
并且**加了一个校验脚本把这件事钉死**（CI 也跑它）：

```bash
uv run --with jsonschema python scripts/validate_manifests.py
```

```
✅ .claude-plugin\marketplace.json
✅ plugins\crop-breeding-expert\.claude-plugin\plugin.json
✅ plugins\evolutionary-biology-expert\.claude-plugin\plugin.json
✅ plugins\evolutionary-ecology-expert\.claude-plugin\plugin.json
✅ plugins\hybrid-speciation-expert\.claude-plugin\plugin.json
✅ plugins\infographic-viz\.claude-plugin\plugin.json
✅ plugins\slidev-generator\.claude-plugin\plugin.json

7 个 manifest，0 个不合规，0 个有告警
```

这个脚本做三件事，**每一条都对应一种真实踩过的坑**：

| 检查 | 抓什么 |
|------|--------|
| `$schema` 地址能取到 JSON（不是 HTML、不是 404） | 官方地址失效 → 编辑器补全静默消失 |
| 按 schema 校验字段类型 / 必填项 | 字段写错时 `claude plugin validate` 未必拦得住 |
| 顶层字段是否都在官方字段表里 | **Claude Code 会静默剥离**不认识的字段 |

> `$schema` **在加载时被忽略**，所以填错不会让插件加载失败 ——
> 但填一个 404 地址意味着**编辑器的自动补全彻底没有**，还会误导读代码的人。

### ⚠️ 本机实测发现的三个问题

```text
# 1. 插件安装缓存是迁移前的旧快照
Loaded 0 skills from plugin evolutionary-biology-expert default directory
Loaded 1 agents from plugin evolutionary-biology-expert default directory
```

仓库里已经迁移到 `skills/<name>/SKILL.md` 了，但 `installed_plugins.json` 登记的还是
旧版本目录（里面还是平铺的 `skills/*.md`）→ **skill 一个都没加载，agent 却加载了**。

实测确认**根因是缓存跟的是远端已发布版本**，不是布局写错：
`claude plugin update` 把缓存从 `a4fe7f85f932` 换成了 `fb9f4c38a2c1` ——
后者正是**远端 main 的 HEAD**（迁移还没 push），缓存里依然是旧布局。
改用 `claude --plugin-dir ./plugins/evolutionary-biology-expert` 就地加载，
日志立刻变成 `Loaded 4 skills from plugin evolutionary-biology-expert`。

**2. 4 个插件整体加载失败（市场缓存过期）** —— 日志见 [07 排错手册 · 坑 3](07-排错手册.md#坑-3-4-个插件整体加载失败-市场副本过期)。

`known_marketplaces.json` 里 `cc_plugins` 的 `lastUpdated` 是 **2026-01-08** ——
市场副本早就过期了。

```text
# 3. 插件 agent 的 frontmatter 有两个不认识的字段
[WARN] Plugin agent file …/agents/evolutionary-biology-analyst.md has frontmatter keys
       Claude Code does not recognize or apply: "version", "input_schema"
```

`version` 和 `input_schema` **不是 agent 的合法字段**（合法的见
[05 多代理编排 · frontmatter 全表](05-多代理编排.md#自定义-subagent-的-frontmatter-全表)）。
不致命，但会一直刷警告。

### 修复动作

```bash
claude plugin marketplace update cc_plugins   # 刷新市场副本
claude plugin update --all                     # 重装插件（会重新复制到缓存）
```

> 调试期更快的办法：`claude --plugin-dir ./plugins/<name>` **就地加载**，
> 改完源码重启就生效，不用刷缓存。


## ✅ 写插件的检查清单

- [ ] `.claude-plugin/plugin.json` 在**子目录**里，其他文件在**插件根目录**
- [ ] `skills` 指向**目录**，每个技能是 `<name>/SKILL.md`
- [ ] `commands` 指向**平铺的 .md 文件**
- [ ] 所有路径以 `./` 开头，**正斜杠**
- [ ] 路径都存在，且不越出插件根
- [ ] `name` / `description` / `author` 齐全（`--strict` 下缺了会失败）
- [ ] 没有拼错的顶层字段（`--strict` 会抓到）
- [ ] README 里有**一行安装命令**
- [ ] `claude plugin validate ./<插件> --strict` 通过
- [ ] `claude plugin details <插件>` 看 always-on 成本是否可接受
- [ ] 需要的话跑 `claude plugin eval` 验触发率
