# 07 · 排错手册

> **本章要回答的问题**：出问题了，从哪查、怎么查、查到根因？
>
> 答案：**先看 `claude --debug` 的启动日志**。Claude Code 把 90% 的"静默失败"
> 都写在那里面 —— 它不报错、不提示、只是不加载。

## 🔬 诊断方法论（本文档的核心）

### 三层证据源

| 层 | 工具 | 能看到什么 | 权威度 |
|----|------|-----------|-------|
| **1. 启动日志** | `claude --debug` | 实际加载了什么、跳过了什么、为什么 | ⭐⭐⭐ **最权威** |
| **2. 官方校验命令** | `claude plugin validate` / `claude plugin details` | manifest 是否合规、插件成本 | ⭐⭐ |
| **3. 交互式命令** | `/context` `/skill-doctor` `/doctor` `/plugin` | 运行时视角的分解 | ⭐⭐ |

> **原则：先跑 1，再看 2，最后用 3 确认。**
> 猜是没用的 —— Claude Code 的"静默失败"太多，猜错方向只会浪费时间。

### 标准诊断流程

```bash
# 1) 起一个最小会话，把启动过程完整记录下来
claude --debug -p "回复 OK 两个字即可"

# 2) 找到这次会话的日志文件（按时间排序，最新的那个）
ls -t ~/.claude/debug/*.txt | head -1

# 3) 按症状 grep
LOG=$(ls -t ~/.claude/debug/*.txt | head -1)
grep -iE "skill|agent|plugin" "$LOG" | head -40
```

**调试期还有两个开关**：

```bash
claude --debug --verbose      # 更啰嗦
claude --debug <插件名>       # 只看某个插件相关的日志
```

### 日志里的关键字速查表

| 症状 | grep 关键字 | 含义 |
|------|------------|------|
| skill 没被加载 | `Loaded [0-9]+ unique skills` | 数字比你预期的少 |
| skill 清单超预算 | `Skill listing over budget` | description 被截断，Claude 看不见后面的 skill |
| frontmatter 解析失败 | `Failed to parse YAML frontmatter` | 该文件被**静默忽略** |
| 字段名不认识 | `does not recognize or apply` | 字段拼错了 |
| 插件 skill 为 0 | `Loaded 0 skills from plugin` | 布局不对，或缓存是旧的 |
| 插件整体没加载 | `not cached at` / `plugin-cache-miss` | 市场副本过期，要刷新 |
| 权限被拒 | `Permission deny rule` | 规则写错了或匹配不上 |
| 沙箱相关 | `sandbox` | 原生 Windows 上没有沙箱 |

### 把这套流程固化成脚本

本仓库已经把"数常量"这一步自动化了：

```bash
uv run --with pyyaml python scripts/measure_context.py
```

它会逐个来源统计 skill / agent 的 `description` 字符数与 token 估算，
并且**标出 frontmatter 解析失败的文件**和**不会加载的旧平铺布局**。输出样例见 [02 上下文经济学](02-上下文经济学.md)。

## 🐛 本仓库真实踩过的 6 个坑

### 坑 1：frontmatter 解析失败 → 文件被静默忽略

**症状**：skill 明明写了，Claude 就是不调用它；`/skills` 里也看不到。

**日志**：

```text
[WARN] Failed to parse YAML frontmatter in .claude\skills\explore\SKILL.md: YAML Parse error: Unexpected token
[ERROR] [skills] YAML frontmatter in …\explore\SKILL.md failed to parse and was ignored
```

**本仓库实际有 4 个这样的文件**：

| 文件 | YAML 报错 | 原因 |
|------|----------|------|
| `.claude/skills/explore/SKILL.md` | `Unexpected token` | `argument-hint: [topic] [parallel]` —— 两个相邻的流式序列 |
| `.claude/agents/python-zen-coding-expert.md` | `Unexpected token` | `description:` 是纯标量，里面含 `: ` |
| `~/.claude/agents/story-generator.md` | `Multiline implicit key` | 多行 `description` 没有块标量 |
| `~/.claude/agents/dev-planner.md` | `Multiline implicit key` | 同上 |

**修法**：

```yaml
# ✘ 两个相邻的流式序列
argument-hint: [topic] [parallel]

# ✔ 加引号
argument-hint: "[topic] [parallel]"
```

```yaml
# ✘ 纯标量里含 ": "
description: 编写代码时: 遵循 Python 之禅

# ✔ 整句加引号
description: "编写代码时: 遵循 Python 之禅"

# ✔✔ 多行文本用块标量（推荐）
description: |
  编写代码时遵循 Python 之禅：
  优先可读性，其次简洁性。
```

> **一条规律**：**frontmatter 里的多行文本一律用 `|` 块标量**。
> 这能消灭 80% 的 YAML 解析失败。

**批量检查**：

```bash
claude plugin validate .claude/skills     # 只查这一个目录
uv run --with pyyaml python scripts/measure_context.py   # 全量，并标出失败文件
```

### 坑 2：插件 skill 一个都没加载 → 缓存是迁移前的旧快照

**症状**：`evolutionary-biology-expert` 的 agent 能用，4 个 skill 全都不在。

**日志**：

```text
Loaded 0 skills from plugin evolutionary-biology-expert default directory
Loaded 1 agents from plugin evolutionary-biology-expert default directory
```

**修法**：

```bash
claude plugin marketplace update cc_plugins   # 先刷新市场副本
claude plugin update --all                     # 再重装（重新复制到缓存）
```

**调试期绕过缓存的办法**（改一行就生效，不用刷新）：

```bash
claude --plugin-dir ./plugins/evolutionary-biology-expert
```

> **推广成一条规则**：改了仓库里的插件源码，本机的插件**不会自动更新**。
> 插件是"安装到缓存再加载"的模型。详见 [06 插件与市场](06-插件与市场.md#插件是什么)。

### 坑 3：4 个插件整体加载失败 → 市场副本过期

**日志**：

```text
Plugin loading errors: Plugin "context7" not cached at …\marketplaces\claude-plugins-official
— run /plugin to refresh, Plugin "slidev-generator" not cached at …\marketplaces\cc_plugins
— run /plugin to refresh, Plugin "agent-sdk-dev" not cached at …, Plugin "gopls-lsp" not cached at …
```

**根因**：`known_marketplaces.json` 里 `cc_plugins` 的 `lastUpdated` 是 **2026-01-08**。
市场副本很旧，新插件自然不在。

**修法**：

```bash
claude plugin marketplace update cc_plugins   # 或在会话里执行 /plugin 刷新
```

**怎么提前发现**：见 [06 插件与市场](06-插件与市场.md)。

### 坑 4：`Write(.env*)` 这条 deny 规则**根本不生效** ✅ 本仓库已修复

**症状**：以为 `.env` 被保护了，其实没有。

| 写法 | 是否被文件权限检查匹配 |
|------|------------------------|
| `Write(.env*)` | ❌ **不匹配**（启动时告警） |
| `Edit(.env*)` | ✅ 匹配，且覆盖**所有**文件编辑类工具 |

> **本仓库已修复**：`.claude/settings.json` 的 deny 列表已从 `Write(.env*)` 改成 `Edit(.env*)`。
> 下次启动时那条告警应该消失了 —— **如果还在，说明改的不是生效的那份配置**（见「其他常见症状」）。

详见 [04 权限与护栏 · 发现 2](04-权限与护栏.md#发现-2-Write-env-这条规则根本不会生效-已修复)。

### 坑 5：skill 清单超预算 → Claude 根本不知道那些 skill 存在

**日志**：

```text
[WARN] Skill listing over budget: 145 skills, 46109 chars > 6000 budget
       — descriptions will be truncated.
       Run /skills to disable some, or raise skillListingBudgetFraction in settings.
```

**后果不是"描述变短"**，而是：**排在后面的 skill 的 `description` 被整个截掉 →
Claude 不知道它们存在 → 永远不会被调用。**

**修法**：

```bash
/skills        # 停用当前项目用不到的 skill
```

或调高 `settings.json` 里的 `skillListingBudgetFraction`。

详见 [02 上下文经济学 · 问题 1](02-上下文经济学.md#问题-1-skill-清单超预算-主因在用户级目录)。

### 坑 6：官方文档自相矛盾 → 以二进制为准

**症状**：按 [interactive-mode](https://code.claude.com/docs/en/interactive-mode) 的说法，
"Claude 工作时按 `Enter` 会排队"。实际按了 `Enter`，消息**立刻发出并打断了当前轮**。

**根因**：官方两个页面在这一点上不一致。

| 来源 | 说法 | 权威度 |
|------|------|-------|
| [interactive-mode](https://code.claude.com/docs/en/interactive-mode) §Queue messages | "press `Enter` … queues the message" | ❌ **v2.1.247 之前的旧行为，未更新** |
| [keybindings](https://code.claude.com/docs/en/keybindings) §Chat actions | `chat:submit`=`Enter`=Submit message；`chat:queueSubmit`=`Ctrl+X Enter`=queues it and **never interrupts the turn**（需 v2.1.247+） | ✅ 权威 |
| 本机二进制（2.1.314） | `enter:"chat:submit"`、`"ctrl+x enter":"chat:queueSubmit"` | ✅ 事实 |

**修法**：排队用 **`Ctrl+X Enter`**；`Enter` 是 `chat:submit`（立即发送，会打断）。

**怎么自己验证（二进制里有出厂默认值）**：

```bash
uv run python scripts/extract_keybindings.py --context Chat
```

输出（2.1.314 实测节选）：

```text
  enter           ->  chat:submit
  ctrl+x enter    ->  chat:queueSubmit
  ctrl+enter      ->  chat:sendNow
  ctrl+x ctrl+s   ->  chat:sendNow
  ctrl+j          ->  chat:newline
  escape          ->  chat:cancel
  up              ->  history:previous
  down            ->  history:next
```

> **推广成一条规则**：**官方文档也会过时**。
> 当文档和你的实测冲突时，把二进制当最终事实源 —— 出厂默认键位、动作名、
> 版本门槛都写在里面。查文档先看 [keybindings](https://code.claude.com/docs/en/keybindings)，
> 它比 [interactive-mode](https://code.claude.com/docs/en/interactive-mode) 更新得更勤。

**另一个二进制里能挖到的东西：CHANGELOG**。
Claude Code 把最近 13 个版本的 release notes 打包进了可执行文件：

```bash
uv run python scripts/extract_changelog.py                # 写到 tmp/claude-changelog.md
uv run python scripts/extract_changelog.py --since 2.1.305
uv run python scripts/extract_changelog.py --grep queue   # 只看匹配的条目
```

[08 演进趋势](08-演进趋势.md) 一章的"近期 release 说了什么"就是从它来的。

## 🔍 其他常见症状

### 改了配置没生效

| 原因 | 检查 |
|------|------|
| 改了插件源码但没刷新安装 | `claude plugin update --all` 或用 `--plugin-dir` 就地加载 |
| 改了 `settings.json` 但被更高优先级覆盖 | `/config` 看实际生效值；检查 managed settings |
| 项目设置里没生效 | **插件配置不读项目级 settings**（日志：`project settings are not read`） |
| 改完要重启 | 多数组件在会话启动时加载；`/reload-plugins` 只切换插件 |

### 权限弹窗没出现 / 出现了不该出现的

| 症状 | 原因 |
|------|------|
| 裸工具名 allow 之后工具**整个从上下文消失** | `"allow": ["Bash"]` 是**移除工具**，不是"免批准"。见 [04](04-权限与护栏.md#三类规则) |
| `permissions.allow` 里写了 `.claude/` 也写不进去 | **受保护路径**永远不自动批准。见 [04](04-权限与护栏.md#受保护路径-protected-paths) |
| `Bash(command:rm *)` 没生效 | 主内容字段**不能用参数匹配**。见 [04](04-权限与护栏.md#参数匹配的-6-条限制) |

### 上下文突然"忘了"刚说过的话

这是**压缩**（compaction）不是 bug，保留与丢弃规则见 [02 上下文经济学](02-上下文经济学.md#压缩-compaction-到底保留了什么)。

### 命令跑了一半 Claude 不动了

大概率是**在等权限确认**。检查：

- 终端底部是不是有弹窗（切到别的窗口了？）
- `/plugin` 或 `/doctor` 里有没有待处理项
- `Ctrl+C` 取消当前输入，`Esc` 打断当前轮

## 📋 一张"症状 → 动作"的速查表

| 症状 | 第一步做什么 |
|------|------------|
| skill / agent 没生效 | `claude --debug -p hi` → grep `Failed to parse` |
| 插件内容没更新 | `claude plugin update --all`（或 `--plugin-dir` 就地调试） |
| 插件整体不加载 | `claude plugin marketplace update <name>` |
| 权限规则不生效 | 看启动告警；确认写的是 `Edit(...)` 而不是 `Write(...)` |
| 上下文很贵 | `/context` 看分解；`/skills` 停用不用的 skill |
| manifest 校验失败 | `claude plugin validate <path> --strict` |
| 想知道插件花了多少 | `claude plugin details <name>` |
| 不确定改了什么生效 | `/context` 看加载了哪些 CLAUDE.md 和 memory |

## 🧰 建议加进项目的工具

```bash
# 校验所有插件
for p in plugins/*/; do claude plugin validate "$p" --strict; done

# 校验市场
claude plugin validate .claude-plugin/marketplace.json --strict

# 常驻成本体检
uv run --with pyyaml python scripts/measure_context.py

# frontmatter 合规性（静默忽略的元凶）
uv run --with pyyaml python scripts/validate_skills.py

# 出厂键位 / 最近 release
uv run python scripts/extract_keybindings.py --context Chat
uv run python scripts/extract_changelog.py --since 2.1.305
```

本仓库已有的校验脚本：

| 脚本 | 查什么 |
|------|--------|
| `.github/scripts/check_references.py` | Markdown 里引用的文件是否存在 |
| `.github/scripts/check_mcp_dependencies.py` | MCP 依赖是否声明齐全 |
| `.github/scripts/validate_content.py <plugin>` | 插件内容质量 |
| `scripts/measure_context.py` | **常驻上下文成本 + frontmatter 体检** |
| `scripts/validate_skills.py` | **全仓库 skill/agent frontmatter 合规性**（YAML 能否解析、name 与目录名是否一致） |
| `scripts/extract_keybindings.py` | **出厂默认键位表**（从二进制提取） |
| `scripts/extract_changelog.py` | **内嵌 CHANGELOG**（从二进制提取最近 13 个版本） |

> `scripts/validate_skills.py` 已在 CI 里跑：
> `plugins/` 范围**阻塞式**（必须 0 错误），`.claude/` 范围**非阻塞**（当前有 5 个历史遗留错误，
> 修完就可以升级为阻塞式）。
